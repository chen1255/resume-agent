# 面试追问与参考回答

按考察意图分类。原则：**讲清边界（哪些是我做的、哪些复用框架），用机制回答，不用形容词回答。**

## A. 项目定性

**Q1：这个项目里哪些是你做的？**
A：运行时（LangGraph 编排、沙箱、Web 控制台）复用 DeerFlow 开源框架；我独立完成的是应用层四件事：① SOUL 人设设计，把 HR 业务规则写成行为契约；② 三个 Skill 技能包，把评估、批量筛选、面试题生成固化为标准流程和输出模板；③ 通过 MCP 协议设计并接入候选人 SQLite 库，定义表结构和聚合场景；④ 全栈部署、工具权限收敛与隐私配置（关闭长期记忆、敏感列不建表）。

**Q2：这跟直接用一个对话框调 ChatGPT 有什么区别？**
A：三点：① **流程被固化**——评分维度、权重、证据绑定写在 Skill 里，十份简历同一把尺子，ChatGPT 每次自由发挥、口径会漂移；② **能安全地操作数据**——MCP 给模型的是结构化、有 schema、有白名单的工具，而不是放开 shell；③ **有业务边界**——人设文件规定"不自动淘汰、不基于敏感属性评分"，这类治理规则靠纯 Prompt 在长对话里不稳定。

**Q3：为什么选 DeerFlow，不自己从零写？**
A：需求核心是验证"垂直 Agent 的业务设计"而不是重造运行时。评估过 LangGraph 手写和几个框架后选它：文件即配置的 Agent/Skill 布局可版本管理，MCP 是一等公民，且自带鉴权和控制台，能把时间花在业务资产（人设、技能、数据模型）上。我也改了它的默认配置（agents_api 开关、扩展配置、Windows 兼容），不是纯开箱。

## B. Agent 机制

**Q4：模型怎么知道什么时候用哪个技能？**
A：两条路径。默认是被动发现：技能的 name + description 渲染进系统提示词，ReAct 循环里模型按当前意图语义匹配；需要确定性时用户可用 `/技能名` 斜杠强制激活，仅当轮生效。技能白名单还会在沙箱投影层再过滤一次，属于纵深防御。

**Q5：Agent 怎么决定调 SQL？怎么防止它乱执行？**
A：MCP 握手时 Gateway 拿到每个工具的 JSON Schema 和描述，结合我在配置里写的路由关键词（入库、统计、聚合……），相关意图下优先暴露 `candidate-db_*` 工具；模型生成的是结构化参数，不是拼接命令行。安全上：智能体只绑定了这一个 MCP 来源；SQLite 文件是独立的业务库而非系统库；写操作走单独的 `write_query` 工具；技能层还约束"只写结构化评估字段，不存联系方式"。

**Q6：MCP 是什么？为什么不用 Function Calling 直连？**
A：MCP 是工具提供方与模型之间的标准协议（stdio/HTTP 传输 + JSON-RPC 握手 + tools/list 发现）。相比把函数硬编码进应用代码，它的收益是：工具服务独立进程、可独立升级；换模型/框架时工具契约可移植；服务发现、前缀隔离、路由、超时都是平台统一管的。代价是多一跳进程通信和首跑拉起成本，本地 SQLite 场景完全可接受。

**Q7：人设（SOUL）和技能（SKILL）有什么区别？会不会重复？**
A：不重复，是"道"和"术"。SOUL 是恒定的身份与边界（我是谁、不替人决策、合规红线），每轮都在；Skill 是任务态的方法论（评分表长什么样、批量流程几步），按意图加载、可插拔、可独立复用和分发。

## C. 可靠性与质量

**Q8：怎么保证评分客观、模型不乱编？**
A：三层：① **证据绑定**——Skill 要求每个评分附简历原文依据，并区分【事实】和【推断】；② **结构化抽取**——字段缺失标"未提供"，禁止补全；③ 疑点（时间空白、措辞夸大）只以"建议核实"中性呈现。这不能消灭幻觉，但让幻觉可被 HR 一眼审计。后续我会加标注评估集做回归。

**Q9：批量处理时一致性怎么保证？**
A：统一 schema 解析 → 同一权重表打分 → 模板化输出；并且要求所有候选人在同一轮上下文里按同一标准评完，而不是分会话各评一次。硬门槛只标"存疑"不自动剔除，避免规则错杀。

**Q10：简历是敏感数据，你怎么考虑隐私？**
A：会话层面关闭长期记忆，防止 A 的信息进入 B 的上下文；存储层面只把结构化评估字段入库，联系方式等敏感列不建表；输出层面禁止基于性别、年龄、籍贯、婚育等做评分，并对 JD 中的歧视性表述做合规提醒。如果上生产，还需要补传输加密、留存周期和权限审计，我会明确说明这是本地演示版的边界。

## D. 工程细节（真实踩坑）

**Q11：部署中遇到过什么问题？**
A：两个印象深的：① Windows 上 `mcp-server-sqlite` 拉起来就报 `AttributeError: 'Server' object has no attribute 'list_resources'`，根因是 PyPI 旧 server 与最新 mcp SDK 的 API 漂移，用 `uvx --with mcp==1.2.1` 锁版本解决；② GUI 启动的进程 PATH 里没有 uvx，stdio MCP 的 command 必须配绝对路径，这类问题靠 JSON-RPC 握手探针逐段定位，而不是猜。

**Q12：为什么工具只给文件读写，不给 bash 和联网？**
A：最小权限。简历分析的动作空间是"读简历 → 写报告/CSV → 调数据库"，bash 和 web 不在需求内；每多一个工具就多一类提示注入后的攻击面（比如简历正文里藏指令让模型执行命令）。需要联网查公司信息时再单独评估放开。

## E. 演进与度量

**Q13：下一步会做什么？**
A：优先级排序：① 标注一个小规模评分评估集，量化每次 Prompt/模型变更的一致性；② 接岗位知识库做 RAG，引入历史录用样本校准评分；③ 飞书渠道化（群里转发简历即触发）；④ 大批量异步化（MCP 任务契约 submit/status）；⑤ 多智能体（筛选 lead + 薪酬/背调子代理）。

**Q14：效果怎么衡量？**
A：演示指标（单份报告耗时、批量处理份数）只能说明能跑；真正有效的指标是业务指标：HR 对报告的采纳率、评分与人工评分的相关系数、面试后复盘的"评估命中/误判率"。没有业务标注前，我不会在简历上写"准确率 XX%"这类无法自证的数字。
