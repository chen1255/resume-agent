# 批量简历筛选技能（batch-screening）

把多份简历纳入**同一把尺子**：统一解析字段、统一评分标准、横向可比，并沉淀结构化数据。

## 触发逻辑

- **触发方式**：用户提供 2 份及以上简历，要求对比 / 排序 / 筛选 / 统计 / 导出名单。
- **触发时机示例**：
  - "这是 JD 和 8 份简历，帮我排个序"
  - "对比下这几个候选人，导出一张表"
  - "/batch-screening 这批简历里哪些最匹配高级前端岗"
- **不触发**：只分析 1 份 → `candidate-report`。

## 输入要求

| 输入 | 必需 | 缺失处理 |
|---|---|---|
| 2 份以上简历 | 是 | 不足 2 份时提示并转 `candidate-report` |
| 目标岗位 JD | 强烈建议 | 先询问一次；无 JD 则使用通用标准，并在表头注明"通用标准，非岗位定制" |
| 筛选硬门槛 | 否 | 有则先做硬门槛预检（如"本科以上、5 年+"），**不直接淘汰**，标记为"门槛存疑"交人工确认 |

## 工作流程（严格按序）

1. **建立统一档案 schema**：姓名 / 学历 / 总年限 / 最近两家公司与职位 / 核心技能 / 管理经验 / 跳槽频率 / 期望，逐份提取，字段缺失写"未提供"。
2. **统一评分**：所有候选人使用同一维度与权重（技能 35%、经验 25%、项目匹配 25%、稳定性 15%），**禁止对不同候选人使用不同标准**；评分依据必须可追溯到简历原文。
3. **硬门槛预检**：对用户给的硬条件逐项标记，不满足只标"存疑"，不自动剔除。
4. **排序与分层**：按综合分降序，分为 A 优先面试 / B 可面 / C 待观察，分层理由各一句话。
5. **批次统计**：学历分布、年限区间分布、关键技能覆盖率等简表（仅基于简历事实）。
6. **结构化入库**（可选）：当环境提供 `candidate-db` MCP 数据库工具时，把每份候选人的结构化档案写入 candidates 表，便于后续用 SQL 做批次查询与跨批次对比；入库前向用户说明将写入本地数据库。
7. **导出**：默认输出 Markdown 对比表；用户要求 CSV 时，按 `templates/comparison_template.md` 的列顺序生成 CSV，用 Write 保存到 `/mnt/user-data/outputs/`，文件名 `候选人对比_{岗位}_{yyyyMMdd}.csv`。

## 输出格式

- 主输出：候选人对比总表（Markdown 表格，列见模板）。
- 附：A/B/C 分层名单 + 批次统计简表 + 数据缺口提示（哪些候选人信息不全）。
- 对比超过 15 人时，正文只展示总表与 A/B 名单，全量明细写入文件。

## 禁止事项

- 禁止仅凭单一维度（如学历）排序；禁止对不同候选人使用不同评分尺度。
- 禁止自动淘汰候选人；禁止替用户发出面试通知或承诺 offer。
- 禁止在排序中使用与岗位无关的敏感属性（性别/年龄/籍贯/婚育/健康）。
- 简历信息不得写入长期记忆；写入数据库仅限结构化评估字段，不存联系方式等敏感列，除非用户明确要求。
