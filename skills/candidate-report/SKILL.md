# 候选人评估报告技能（candidate-report）

把一份简历转化为**结构统一、证据可追溯、事实与推断分离**的候选人评估报告。
本技能只产出分析，不替代 HR 决策。

## 触发逻辑

- **触发方式**：用户上传 1 份简历（PDF/Word/图片/文本）并要求分析、评估、出报告、画像。
- **触发时机示例**：
  - "帮我分析这份简历"
  - "这是 Java 后端的 JD，评估一下这个候选人"
  - "/candidate-report 看看这个产品经理候选人"
- **不触发**：多份简历批量对比 → 改用 `batch-screening`；只需要面试题 → 改用 `interview-prep`。

## 输入要求

| 输入 | 必需 | 缺失时的处理 |
|---|---|---|
| 简历全文/文件 | 是 | 请用户上传，不要凭空编造候选人 |
| 目标岗位 JD | 否 | 先询问一次；用户表示没有则按"通用胜任力评估"执行，并在报告中标注"无 JD，匹配分为通用评估" |
| 评分维度权重 | 否 | 使用默认权重（见下），不反复追问 |

## 工作流程（严格按序）

1. **结构化解析**：按 `templates/report_template.md` 的"候选人档案"提取字段；OCR/原文缺失字段标注"未提供"，**禁止猜测补全**。
2. **事实/推断分离**：每条评价标注来源——【事实】=简历原文可直接支持；【推断】=基于经历的合理推测。
3. **JD 逐项匹配**：拆 JD 为硬性条件（学历/年限/必备技能）与加分项，逐项判定 ✅满足 / ⚠️部分满足 / ❌不满足 / ❓无法判断，并引用简历依据。
4. **量化评分**（0-100）：技能匹配 35%、经验年限与相关性 25%、项目/业务匹配 25%、稳定性与成长轨迹 15%。每个子项给分必须写一句依据。
5. **亮点与疑点**：亮点给证据；疑点按类型分类（时间空白、经历矛盾、措辞夸大、频繁跳槽、信息缺失），以"建议核实"的中性语气呈现。
6. **面试建议**：针对疑点和关键能力缺口，提出 3-5 个具体追问方向。
7. **推荐结论**：默认**不给**。仅当用户明确要求"推荐吗/要不要推进"时，才在报告末尾给出带置信度（高/中/低）的建议，并附固定声明。

## 输出格式

- 完整报告严格使用 `templates/report_template.md` 的章节结构。
- 报告以 Markdown 输出；用户要求保存时，用 Write 写入沙箱 `/mnt/user-data/outputs/` 目录，文件名格式 `评估报告_{候选人姓名}_{yyyyMMdd}.md`。
- 评分表、匹配项一律用表格，方便 HR 快速扫描。

## 禁止事项

- 禁止基于性别、年龄、籍贯、婚育、健康、民族等与岗位无关的敏感信息加减分或暗示；发现 JD/简历含歧视性表述时提醒合规风险。
- 禁止使用"绝对要/绝对不要"等绝对化措辞；禁止替 HR 做录用承诺。
- 禁止把推测当事实陈述；禁止编造简历中不存在的公司、学校、项目。
- 简历内容仅用于本次分析，不写入长期记忆，不向无关上下文复述。
