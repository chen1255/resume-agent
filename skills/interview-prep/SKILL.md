# 面试准备技能（interview-prep）

把"看简历 → 设计问题"沉淀成标准化动作：每题都有**考察点 + 期望信号 + 危险信号 + 评分要点**，让面试可评估、可对比。

## 触发逻辑

- **触发方式**：用户要求针对某岗位/某候选人准备面试问题、提纲、评分表。
- **触发时机示例**：
  - "给这个 Java 候选人出一面题"
  - "针对他简历里这个项目我该怎么追问"
  - "/interview-prep 产品经理二面，候选人是这份简历"
- **不触发**：只要简历评估报告 → `candidate-report`。

## 输入要求

| 输入 | 必需 | 缺失处理 |
|---|---|---|
| 候选人简历 | 否 | 无简历则产出**岗位通用题库**，并注明"无针对性追问" |
| 岗位 JD | 否 | 无 JD 时按岗位通用能力模型出题并注明 |
| 面试轮次 | 否 | 默认一面（基础 + 项目深挖）；可指定二面/终面（系统设计、管理、价值观） |
| 时长 | 否 | 默认 60 分钟，按时间控制题量 |

## 题目结构（必须四类齐全）

1. **简历疑点追问**（3-4 题）：直接引用简历原文中的具体表述（如"主导""从零搭建""性能提升 60%"），追问真实贡献度、数据口径、技术细节、时间线矛盾。
2. **岗位硬技能题**（3-4 题）：对齐 JD 必备技能，至少 1 题为"是什么/为什么"的基础题、1 题为"踩过什么坑"的经验题。
3. **场景 / 系统设计题**（1-2 题）：给一个该岗位真实会遇到的小场景，观察拆解与权衡，而非标准答案。
4. **行为面试题**（2 题）：用 STAR 框架引导（冲突处理、失败复盘、推动协作），问真实事件而非观点。

## 每题的输出格式

```
Q{n} [类别] 问题正文
- 考察点：……
- 期望信号（2-3 条）：……
- 危险信号（2 条）：……
- 追问分支：若答出 A 则追问 ……；若含糊则降级问 ……
- 评分要点（1-5 分锚点）：1分=… / 3分=… / 5分=…
```

## 工作流程

1. 解析简历，列出 3-5 个最值得追问的点（疑点 + 关键成就）。
2. 对齐 JD 核心能力，确定本轮考察清单（不超过 5 项）。
3. 按四类生成题目，60 分钟默认 9-11 题（含追问）。
4. 末尾生成**面试评分汇总表**（能力项 × 权重 × 1-5 分）与**红线项**（造假、歧视性言论等一票否决观察点）。
5. 用户要求保存时，用 Write 写入 `/mnt/user-data/outputs/`，文件名 `面试题包_{候选人或岗位}_{轮次}_{yyyyMMdd}.md`。

## 禁止事项

- 不出与岗位无关的私人问题（婚育、家庭、健康、信仰等），并提示此类问题的合规风险。
- 不承诺题目难度等于任何公司真题；不生成用于欺骗背调的话术。
- 题目必须基于简历/JD 中的真实信息，不虚构候选人经历再"戳穿"。
- 评分锚点保持行为可观察，不使用"眼缘""气场"等主观词。
